# Native formats and manual packages

Reviewed opportunity briefs now admit Short, Reel, carousel, single image, community text and poll treatments. Each selected treatment requires its own format copy. Reels require a Reel caption; image posts require their own image text/caption; polls require a question and two to four distinct bounded options. The underlying three-beat research treatment remains mandatory. This renderer uses original cards and optional cleared stills; a Reel caption alone does not prove a distinct visual treatment or a recut.

A single-image export contains exactly one1080×1350 image and its own caption. Explicit Instagram/Facebook destinations use the existing image review-queue path. It never becomes Ready or publishes merely by rendering/approval. Shorts/Reels remain vertical video; carousel exports preserve slide order.

Community/polls write actual local UTF-8 JSON and text files plus a preview card. Their manifests say manual_only/not_published. Full text/options appear in the owner interface for inspection. After exact-export approval the owner can download either file. These formats cannot create queue items, select accounts, schedule uploads or publish through this integration. Unsupported API capabilities are not inferred.

Manual package downloads require owner credentials and current exact-file approval. A media pass does not authorize private JSON/text downloads; they are absent from the media-file route. Changed/missing package bytes invalidate approval and download. Source refs and input manifests remain attached. Rendering another version keeps the earlier files. Rights and source review remain owner responsibilities; the existing separate native approval flow has not been replaced by the LongForm acceptance UI.
