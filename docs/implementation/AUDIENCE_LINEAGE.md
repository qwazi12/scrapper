# Audience snapshots and exact content lineage

Private YouTube Analytics is an explicit read-only sync through an existing grant configured in `YOUTUBE_ANALYTICS_AUTHORIZED_USER_JSON`. The grant must declare `https://www.googleapis.com/auth/yt-analytics.readonly`; the app creates no OAuth flow or broader grant. The reporting endpoint is fixed, uses GET, sends credentials in headers and follows no redirects. Missing configuration, ownership/report errors, unsupported columns and empty tables remain distinct unavailable/missing results. Instagram/Facebook still require authorized owner exports. No real grant or account was accessed during this implementation.

Requests bind a canonical channel and video to a reviewed local source. First query the most recent returned complete reporting day, then ask the provider for the aggregate through that day. Keep provider averages; do not average daily averages locally. Measurements use the end of the processed Pacific day, while fetch time is retained separately. Empty data does not become zero. Unsupported impressions/clicks stay NULL. Average viewed percentage has its own metric and may exceed100%; it is not squeezed into the older bounded retention-percent field. The inclusive first Pacific reporting day can include activity before the owner's exact publication time; intraday isolation is unavailable and comparisons remain descriptive.

These choices follow the [query reference](https://developers.google.com/youtube/analytics/reference/reports/query), [report definitions](https://developers.google.com/youtube/analytics/channel_reports), [metric definitions](https://developers.google.com/youtube/analytics/metrics), [Pacific date semantics](https://developers.google.com/youtube/analytics/dimensions), and [data latency model](https://developers.google.com/youtube/analytics/data_model). The provider reports processing delay rather than real-time coverage.

ContentLineage is a versioned, append-only database journal. A mapping binds platform/account/content ID, format, exact publication time and a fingerprint of retained Studio/Countdown/native/delivery inputs. The public-to-local match is an owner attestation; public media bytes were not compared. Corrections require the current mapping ID, preserve prior versions/observations, and revoke an in-flight old mapping's worker. Generation checks stop a second request and stale promotion. Raw SQL cannot update/delete mapping evidence. Metadata and full retained manifests require owner credentials.

Studio/Countdown cost snapshots use creation/version windows and explicit request references, including matched later billing adjustments. They state their project-window scope and estimate/attestation basis; they are not marginal per-cut costs or verified invoices. Countdown reused-segment costs remain excluded. Native/delivery sources currently lack reliable request attribution and report NULL/unattributed. Missing cost evidence never becomes a free-production claim.

Observations retain corrections from the provider, including a later return to earlier totals. Active learning selects the latest fetch for a reporting boundary, excludes superseded mappings, and separates account, platform, format and publication age. Experiments require the matching account; blank account selects unlinked owner imports. Historical records remain available. No causal winner or automated growth claim is made.

The owner UI previews exact retained bytes, binds acknowledgment to all mapping inputs, records corrections and triggers explicit read-only sync. It preserves publication timestamp precision when choosing a mapping for authorized observation imports. Merely viewing the page makes no provider request. Source lists expose recent retained records; broader source pagination remains a UX backlog item.
